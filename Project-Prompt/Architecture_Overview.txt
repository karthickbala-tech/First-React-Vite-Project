                            DATA FLOW EXAMPLES
═════════════════════════════════════════════════════════════════════════════════

EXAMPLE 1: Dashboard Loads
─────────────────────────

1. User opens Zoho CRM → navigates to Account/Deal → Web Tab loads
2. ZOHO.embeddedApp.on("PageLoad") triggers
3. Current user ID, record, module sent to FastAPI backend
4. Backend verifies user can access this record (CRM permission check)
5. Backend queries PostgreSQL for real sync metrics
6. Dashboard calculates: total_attachments, synced, failed, success_rate
7. All metrics come from PostgreSQL sync_logs (real data from actual sync engine)
8. Dashboard displays animated KPI cards with real numbers
9. Auto-refresh every 30-60 seconds fetches latest metrics
10. All without repeated Zoho/Drive API calls (uses database cache)

Result: User sees real sync statistics in <2 seconds


EXAMPLE 2: User Asks AI Question
─────────────────────────────────

1. User types: "Find quotation for ABC Private Ltd"
2. Query sent to /api/chat/messages endpoint
3. Backend checks scope: "Current Record" (default)
   └─ Uses current Deal ID and user's accessible records
4. Hybrid retrieval searches PostgreSQL + pgvector
   ├─ Semantic: Find docs semantically similar to query
   ├─ Keyword: Find "quotation" and "ABC" in file names
   ├─ Metadata: Filter by crm_module='Deals', crm_record_id=current
   └─ Permission: Verify user can access each result
5. Top 3 documents retrieved with confidence scores
6. Results sent to OpenAI GPT-4 with instructions:
   "Here are the most relevant quotations. Answer the user's query based on content."
7. OpenAI reads actual document text (from vector database chunks)
8. Generates: "The latest quotation for ABC Private Ltd is ₹2,45,000."
   └─ Includes source file: quotation_ABC_2026-08.pdf
9. Response includes: Direct link to CRM attachment + Google Drive link
10. Interaction logged to audit_logs table

Result: User gets real answer sourced from real document in <3 seconds


EXAMPLE 3: New Document Uploaded to CRM
────────────────────────────────────────

1. User uploads invoice_scan.pdf to Deal in Zoho CRM
2. Existing sync engine detects new attachment
3. Sync engine uploads to Google Drive
4. Sync metadata recorded (real sync event)
5. Background job (Celery) triggered:
   ├─ Download invoice_scan.pdf
   ├─ Detect: PDF with images (scanned)
   ├─ Run OCR: Extract invoice text "INV-2026-1045, Amount: ₹2,45,000"
   ├─ Chunk: Break into logical sections
   ├─ Embed: Generate vector embeddings for each chunk
   ├─ Index: Store in PostgreSQL + pgvector with metadata
   └─ Mark: Document ready for search
6. Document now searchable by AI chatbot
7. User can ask: "What's the invoice amount?" and get instant answer

Result: Real documents become AI-searchable automatically

                          REAL DATA GUARANTEES
═════════════════════════════════════════════════════════════════════════════════

✅ Dashboard Metrics
   └─ Calculated from actual Zoho CRM attachment API + sync metadata
   └─ Never: "42 attachments" (unless that's the real count)

✅ AI Chatbot Retrieval
   └─ Searches real indexed documents from actual synced files
   └─ Sources include actual file names and Google Drive links
   └─ Never: Fabricates answers or fake documents

✅ Sync Status
   └─ Reads from existing real synchronization engine
   └─ Reflects actual success/failure/pending states
   └─ Error messages from actual API responses

✅ Permissions
   └─ Inherited from real Zoho CRM record permissions
   └─ AI respects user's actual access level
   └─ Cannot retrieve unauthorized documents

✅ Audit Trail
   └─ Every chatbot query logged with real user, document, response
   └─ Timestamps reflect actual interaction times
   └─ Can be exported for compliance

✅ OCR Processing
   └─ Runs on real scanned documents from CRM
   └─ Extracted text stored with confidence scores
   └─ Flagged for manual review if low confidence

✅ Embeddings
   └─ Generated from actual document content
   └─ Stored in pgvector with metadata references
   └─ Used for real semantic search

═════════════════════════════════════════════════════════════════════════════════
                        FAILURE STATES (NO MOCKS)
═════════════════════════════════════════════════════════════════════════════════

If Zoho CRM connection fails:
   → Display: "Zoho CRM connection unavailable"
   → NOT: Show fake metrics or last cached values pretending to be current

If document not found:
   → Display: "Could not find documents matching your query"
   → NOT: Make up an answer or fabricate a document

If permission denied:
   → Display: "You don't have access to that document"
   → NOT: Reveal document exists or show any metadata

If OCR fails on scanned doc:
   → Display: "Unable to process this scanned document. Try uploading a PDF with selectable text."
   → NOT: Show fake extracted text

If OpenAI API down:
   → Display: "AI service unavailable. Try again in a moment."
   → NOT: Return a generic response pretending to be from AI

                             TECH STACK SUMMARY
═════════════════════════════════════════════════════════════════════════════════

Frontend:
  └─ React (Web Tab in Zoho CRM)
  └─ TypeScript for type safety
  └─ Recharts/Plotly for animated visualizations
  └─ Tailwind CSS for modern UI

Backend:
  └─ Python 3.10+
  └─ FastAPI (async, REST API)
  └─ Pydantic (validation, serialization)
  └─ python-docx, PyPDF2 (document extraction)
  └─ pytesseract (OCR)
  └─ langchain or custom RAG (retrieval)

Database:
  └─ PostgreSQL 14+
  └─ pgvector extension (vector search)
  └─ SQLAlchemy (ORM)
  └─ Alembic (migrations)

Caching & Jobs:
  └─ Redis (cache, sessions, job queue)
  └─ Celery (background tasks)

AI/ML:
  └─ OpenAI API (embeddings, GPT-4)
  └─ LangChain (optional, for prompt engineering)

Infrastructure:
  └─ AWS App Runner (development)
  └─ AWS ECS/Fargate (production)
  └─ AWS RDS PostgreSQL (database)
  └─ AWS ElastiCache Redis (cache)
  └─ AWS Secrets Manager (API keys)
  └─ AWS CloudWatch (monitoring)
